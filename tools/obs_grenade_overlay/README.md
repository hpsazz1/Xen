# OBS 道具菜单、参考图与 PgUp/PgDn 采集

主机道具操作统一由本插件承载。OBS Browser Source 和 libobs 负责菜单、图片与标记的绘制；桌面窗口属于 OBS 进程，不需要旧 Python 双图窗口、手机选择页面或语音客户端。

OBS 原有中央 320×320 画布继续专门通过 NDI 传给辅机。插件私有源不加入主场景，不改变原有裁剪、NDI 输出或已测试的投掷动作。

## 操作

1. 保持辅机 Xen 的 Runtime 运行。在 OBS“工具 → Xen 道具提示”启用道具菜单、参考图和 PgUp/PgDn 采集，填写辅机接口地址；本机交付默认 `http://192.168.3.20:5015`。
2. 游戏中按小键盘右键呼出或隐藏菜单：NumLock 关闭时用方向右，开启时用小键盘 6。菜单居中，2560宽屏下为1120×640，1920宽屏下约960×548；常规宽度下限960，遇到较小屏幕继续缩小，屏幕宽高各保留32像素总余量，不超过当前屏幕。保留12px圆角和约92%不透明的深色背景。菜单按实际窗口像素渲染，左右列表和参考区域加宽，长中文、英文名称完整换行，卡片状态单独一行，底部消息随内容扩展，不再省略标题。地图和阵营跟随 GSI，按站位或落点分类，鼠标点选即可切换方案。
3. 辅机载入所选方案后，菜单自动消失并将焦点交还游戏，右上角显示站位和瞄点参考。参考卡采用 Codex 暗色背景 #181818、白字和蓝色标记，约 90% 不透明，鼠标穿透。
4. 拿出道具、站到位置、把视角转到瞄点附近，按上键找点、下键投掷；左键取消，End 全局急停。对齐完成或开始投掷后参考卡隐藏，不播放成功提示音。

方案名称去掉已有地图前缀后，第一个空白前是站位，后面全部是点位。例如“T垃圾桶左 快跳台烟”和“T垃圾桶左 快跳台下烟”归在同一个“T垃圾桶左”站位下，瞄点仍各自独立；没有空白的完整名称单独成组，不混入“其他站位”。原T1、CT来源3号等编号仍兼容。按落点列出多个站位时，站位图采用当前选中方案；未选择或所选方案缺图时显示待采，不拿另一普通站位的照片代替。Mirage T1～T5已有带编号标记的出生点共图继续保留。

再次查看参考时重新点选方案，可以选择同一方案。启动、重连、重新开启插件及 PgUp/PgDn 资源刷新都不会重播已经隐藏的旧选择。菜单可再次按右键或按 Esc 关闭；切到其他应用时也会隐藏。

菜单和参考卡均在初始化窗口透明属性后，通过 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 设置 Windows 截图/录制排除，并回读0x11；不能在分层窗口尚未初始化时调用。此能力作用于受支持的系统采集路径，微信截图和实际直播录制仍需现场确认。没有监听Alt+A或按截图快捷键临时隐藏。PgUp/PgDn制作自身仍主动隐藏插件窗口，待桌面更新后再截完整原图，避免卡片混入参考照片。这不改变原中心 ROI 的 NDI 输出。

## 视频与Runtime同步标记

先在辅机开启“设置 → 日志与运行记录 → 详细运行记录”，启动Runtime并确认归档正常。主机保持本插件开启，在游戏前台按 **Ctrl+F7**：屏幕左上角、中央320×320 ROI以外显示两秒唯一 `SYNC-...` 编号。F8仍只启停Runtime。同步不产生游戏键鼠输出，不改变急停参数、OBS画布、NDI场景或原道具窗口的截图排除。

N卡录制需在 `Alt+Z → 设置 → 视频捕获（Video capture）→ 桌面捕获（Desktop capture）` 开启桌面捕获，优先使用能呈现桌面叠层的无边框窗口模式。先录一段短样片，确认成片中确实看到完整SYNC编号；N卡游戏捕获路径可能不包含独立桌面窗口，`WDA_NONE` 只表示本窗口没有主动要求系统排除，并不保证录制工具必然捕获。详见[NVIDIA桌面捕获说明](https://nvidia.custhelp.com/app/answers/detail/a_id/5664)。

录制先开始，再按F8启动Runtime；运行就绪后按Ctrl+F7作为开头锚点，结束前再按一次。出现异常时也可额外标记。每次标记在OBS日志保留编号、GDI绘制调用区间、精确UTC和源机发送/接收及辅机接收/回复四时戳；辅机详细归档保存相同编号及网络时钟映射。HTTP显示“已排队”只表示已接收，是否落盘及有无缺口以辅机归档清单为准。绘制调用完成不是桌面合成完成、显示器扫描或视频PTS，分析时仍须以录像中编号首个可见帧建立锚点，并包含视频帧间隔及捕获延迟误差。

Ctrl+F7只在辅机详细记录/Runtime就绪且F7没有其他控制绑定时注册；重复按住不重触发，标记显示或传输在途时不并行创建新标记。显示请求最多保留两秒，UI或网络迟到会取消旧编号并释放在途状态，不自动重放；传输失败有明确提示。切出游戏会隐藏同步窗；采集PgUp/PgDn前也会主动隐藏，防止编号进入新参考照片。同步状态接口单独失败只关闭同步入口，不清空原有道具提示。此同步功能不要求GSI地图、当前道具选择或参考图就绪。

## PgUp站位图与PgDn瞄点图

PgUp只采集当前方案的站位图；PgDn只采集瞄点图。两者无先后顺序要求，互不覆盖，也不要求另一张图已经存在。每次均隐藏菜单和参考卡后采全屏，自动读取当前已选方案、命名、打包并同步辅机，完成后显示短通知，不自动投掷。只有站位图时也能显示站位参考；只有瞄点图时可直接找点。

PgDn仍应在人工试投成功、恢复原站位与正确瞄角后触发；PgUp可独立拍摄便于辨认站位的画面。无需另开PowerShell或采集监听器，没有二次确认。两张图可采用不同视角，站位图不参与瞄角匹配。

蹲姿瞄点先在Xen把“瞄点姿态”设为蹲姿并保存，再手动按住Ctrl蹲稳后按PgDn。插件同时注册普通PgUp/PgDn以及Ctrl+PgUp、Ctrl+PgDn，进入相同单次采集流程，不会为了采图松开Ctrl；PgDn保存实际画面，不推断人物姿态。以后上键自动蹲下并找点、下键投完释放，蹲W跳投仍使用Xen原时间线；浏览菜单不自动输出。

安装时自动填写主机现有 Python 3 路径；仅使用标准库，没有语音模型依赖。Python 只在这一次内部作业期间运行。OBS 设置中可修改“采集Python”“采集本地目录”“辅机资源目录”；设置保存于 `plugin_config/xen-grenade-overlay/settings.json`，已有值保留。

已有Mirage出生点共用图和标记继续保留，菜单可复用同站位的参考。按PgUp后该方案使用新拍的站位图，不再套用原共用图坐标标记。新方案只登记实际已采的图片。本地原图、短名资源包和发送记录沿用原目录；重复采集保留备份，发送失败保留本地文件。内部文件与状态约定随包保存在 `capture/README.md`，源码位于 `tools/grenade_capture/README.md`。

手机首页不再提供选择入口，HTTP 根路径返回 404；5015 保留为插件读取 GSI、方案、参考图和提交选择的内部接口。语音服务、快捷键和客户端已退役；历史方案中的语音字段只作文件兼容。

## 构建和安装

```powershell
pwsh -NoProfile -File scripts/build_obs_grenade_overlay.ps1 -ObsRoot 'D:\SteamLibrary\steamapps\common\OBS Studio Beta' -SdkRoot 'E:\Xen-deps\obs-studio-32.1.0-rc4-sdk'
```

安装时关闭目标 OBS，再给同一命令追加 `-Install`。可用 `-CapturePython`、`-CaptureRoot`、`-CaptureDestination` 提供首次安装的采集路径；已有设置不覆盖，后续在 OBS 设置修改。脚本不停止进程，也不修改原场景或 NDI 配置；替换插件旧文件时保留 `.previous` 副本。

插件安装在目标 OBS 的 `obs-plugins/64bit` 和 `data/obs-plugins/xen-grenade-overlay`，内部采集文件位于后者的 `capture/`。直接启动 obs64.exe 时，工作目录使用其所在 `bin/64bit`，避免 OBS 找不到语言资源。OBS 相对模块资源路径先解析为实际绝对路径，再生成浏览器文件 URL。

SDK 头文件固定为 OBS 官方 `32.1.0-rc4`（提交 `b7bc979a659a40775904a489eeb0ed9e871e066b`）。导入库由实际目标 OBS DLL 的公开导出生成，只用于此本地 ABI，不冒称官方 SDK 发布包。复用现有 nlohmann/json，不引入 Qt SDK。

此窗口适用于桌面合成的游戏呈现模式，未注入游戏。新菜单的游戏焦点返回、鼠标点选、系统截图排除与 PgUp/PgDn 实际采集需要实机验证；编译、离线测试和接口回执不能代替这些观察。
