# OBS 道具采集内部作业

日常入口只有 OBS 插件：选择方案后，F9 采集当前站位图，F10 采集当前瞄点图。两个功能独立，没有先后顺序；每次只更新对应图片，自动按方案短名打包并同步辅机。制作瞄点图时先人工试投成功，恢复原站位及正确瞄角再按 F10。插件负责热键和作业生命周期；本目录为随插件安装的内部 Python 作业，不需要单独启动工具、安装语音模型或运行常驻 Python 监听器。全部依赖为 Python 标准库。

`worker.py` 只执行一次采集与发送，由插件传入辅机地址、本地资源根、目标共享目录、触发时的游戏窗口/进程、作业状态文件，以及 `--role standing`（F9）或 `--role aim`（F10，兼容旧调用的默认值）；结果写入状态文件后退出。它复用 `capture_once` / `transfer_capture` 流程，不发送游戏输入。F10 本身承载人工试投确认，不增加二次确认；F9 不会替代或重写瞄点的确认时间与几何。

参考目录 `references/<方案stem>/reference.json` 只登记已采集的角色；只有一张图片也能保存、打包和发送，不创建另一张占位图。`capture_complete` 表示双图是否齐全，旧双图清单省略该字段时仍兼容。瞄点图有效时即可用于找点，站位图只作定位说明；只有站位图时，展示站位并等待用户按需采集瞄点。F10 会保留旧站位图及其标记和说明；F9 重采站位时使用当前原图并清除原共享出生点标记。

`aim_plan` 单独保留瞄点采集时的方案快照，旧资源缺省使用其原 `plan`。保存方案后再按 F9，旧瞄点仍可显示和同步，但不会被重新认作新方案的瞄点；按 F10 采集后，瞄点快照才更新到当前方案。此归属检查沿用原有资源与方案一致性要求，不增加确认窗口。

已有 Mirage T1～T5 参考中的共享出生点图保持原样；F9 可用新站位图替换当前方案的旧图。独立首采时不会自动从另一角色或共享图生成未采图片。资源保存在 `references/<方案stem>/`，短名 ZIP 保存在 `packages/<地图>/`；旧资源备份与中断恢复记录保持原格式。发送只更新本次资源，不覆盖原投掷方案。

读取辅机上下文时，F10 沿用 `/capture-context.json`，F9 使用 `/capture-context.json?role=standing`，让服务器按实际采集键判断既有快捷键占用。新路径不改变选中方案与 GSI 上下文的身份核对。

状态中的 `pending` 表示本地资源存在但发送尚未确认；成功需 `state=sent`、`terminal=true` 且进程退出码为0。运行中的进度或异常进程退出不能被当成发送成功。OBS 插件负责同一时刻仅一个作业、超时结束和状态展示。

离线验证为 `tests/grenade_reference_tests.py` 与 `tests/grenade_capture_workflow_tests.py`，使用合成 PNG、本地临时目录和回环 HTTP；不采真实屏幕、不连接辅机、不触发游戏动作。
