# 手机配方练习参考

`XenLineup` 复用现有 Xen 配置，提供局部参考采集、配方选择、定位预览、收藏和人工练习历史。默认沿用当前 320 ROI 采集与传输，不修改原 INI、模型或速度设置。视觉匹配不代表三维站位正确或实际落点成功；Runtime 提供自动对准和独立点按投掷执行路径；目前仅有模拟设备及本地受控进程验证，真实设备与游戏效果仍待验证。不会自动寻找站位。

## 构建与启动

以下是已有开发环境的增量构建入口，命令在仓库根执行。先按[开发指南](development.md#依赖与构建)准备 SDK、CMake 4.2+、PowerShell 7 和测试 Python 环境。脚本默认读取 `build/nvidia/CMakeCache.txt`；README 的基础示例创建的是 `build/CMakeCache.txt`，二者不能混用。已有缓存位于其他目录时传入 `-DependencyCache <实际CMakeCache.txt>`。

缓存还必须显式记录 `FETCHCONTENT_SOURCE_DIR_IMGUI`、`FETCHCONTENT_SOURCE_DIR_NLOHMANN_JSON`、`FETCHCONTENT_SOURCE_DIR_SIMPLEINI`、`FETCHCONTENT_SOURCE_DIR_SPDLOG`，且指向存在的本地依赖源码；普通首次配置未必具备这些项。先在原开发构建中配置并核对这些本地路径，再使用此离线增量脚本；它不负责首次下载依赖。助手输出目录必须与依赖缓存目录不同。

```powershell
pwsh -NoProfile -File .\scripts\build_lineup.ps1
pwsh -NoProfile -File .\scripts\start_lineup.ps1 -CheckOnly
```

构建复用上述 SDK 和依赖源码缓存，产物位于隔离 `build/lineup/Release`。启动脚本默认读取仓库根的 `config.ini`；若沿用 README 自编译应用生成的配置，应传入 `-ConfigPath .\build\Release\config.ini`。`-CheckOnly` 只检查可执行版本和已有配置，不启动网络、采集或设备。正常使用去掉 `-CheckOnly`；现有 INI 位于其他包时用 `-ConfigPath <已有config.ini>`，不复制或重建配置。默认监听 `127.0.0.1:8879`；手机使用时 `-BindAddress` 指定实际私网 IPv4。网页地址、端口及配方数据目录属于助手专用选项，不把采集网络地址误当网页地址。

启动状态显示配置路径、ROI 尺寸、源尺寸依据、GSI 模式及失败原因。配置解析复用 `load_app_config`，保持旧格式迁移兼容；失败保留静态浏览，不修改用户文件。正常采集仅在用户点击开始后打开源。

## 320 局部练习流程

1. 进入“采集与整理”，人工站稳，填写地图、区域、姿态和靠位说明，保存当前 ROI 原图。共用站位编号仅在同地图/阵营/区域内复用；参考 PNG 不带标记。
2. 在冻结局部图内指定瞄点与静态区域，避开手臂、HUD、动态物体。标注生成新参考编号，原参考和历史保留。补齐名称、目标、道具后成为正式配方。
3. 手机按地图、阵营、区域选择配方，核对参考和靠位说明，**人工移动到附近**并确认锁定。可以收藏或加入练习清单；这些操作不会自动切换已锁配方。
4. 人工就位后点击“已就位，定位”，或使用在同一 INI 中自行绑定的定位快捷键。ROI 模式不在后台默认连续全库搜索；只对明确选择和触发的配方进行局部匹配。
5. 只有局部纹理充分、几何一致、瞄点仍在 ROI 内且同帧有效时显示标记。没有识别、天空、重复纹理、视角变化过大或瞄点移出 ROI 时，请按参考人工转向；不输出裁剪外瞄点。局部模式不承诺大范围附近区域自动发现。
6. 人工完成一次练习后点成功、失败或跳过，可记录当次条件。每条历史保存配方版本、参考编号和当时地图/阵营；这只是用户记录，不是自动落点判断。重复请求不会多记；重启恢复收藏、清单和历史。

断源、源会话或几何改变、上下文失效、取消或停止会撤销当前定位，重连不自动重新触发。手机后台/断网不重放写请求。旧帧和迟到图片不能延长标记有效期。“已定位”仅表示视觉匹配；只有 Runtime 读到匹配当前源、几何、后端与条件的真实量测标定，并具备原有焦点/健康/急停许可时，才会自动小步对准。

## 几何、版本和性能边界

ROI 参考使用独立 schema2，旧全帧参考 schema1 可继续由旧全帧入口使用，二者不混匹配。参考保留原尺寸、原点、像素比例、源/编码尺寸和源身份；尺寸或映射变化需要重新确认参考。缺少有效 metadata 时不编造主画面坐标，只在局部手机同帧预览标注。原 1280×720 全帧像素误差不能直接作为 320 局部精度。

保持一个计算帧和一个可覆盖待处理帧，记录丢弃数量。当前帧 ORB 特征在同轮复用；参考缓存上限 32 项、128 MiB 估算内存，参考修订或文件身份变化失效。整轮、加载、特征、匹配及编码分别计量；本机合成对比不等于副机实测提速。大于缓存的库可能反复淘汰，不能声称所有库都有暖缓存收益。

“导出证据”保留最近128条视觉观察和4组抽样图像，不是完整录像。逐次练习完整日志另存于助手数据目录 `practice-events`，接口只返回最近100条及总数；旧配方上的汇总人工验证字段不会被伪造成逐次历史。

## 单 Run 一键离线复盘

```powershell
python -B scripts/review_run.py --run <已有Run目录> --output <新的报告目录>
```

生成 `index.html`、`REVIEW.md`、`review.json`，汇总完整性、异常时间段、可关联截图/画面锚点、配置身份和性能。只读取归档，不更改原始证据；输出目录不能覆盖 Run。缺项降级为未知，仅在来源时钟/会话与哈希足够时关联画面，不把近似时间当逐帧真值。

独立像素重放仍使用：

```powershell
.\build\lineup\Release\XenLineupOffline.exe --reference <参考目录> --frames <图像目录> --output <新目录>
```

`manifest.json` 中的 `aim` 必须来自人工或合成独立真值，坐标为输入局部图像像素；没有真值不计算准确率。ROI 重放还需明确每帧几何，不能借参考图几何推定新图。真实留出按独立录制会话划分，不能随机拆相邻帧。

## GSI 与定位快捷键

默认 `--gsi-mode shared`：新版 Runtime 唯一接收 GSI，助手同一 Windows 登录会话只读本地管道，不另开 GSI 端口。直接共用同一已有 INI；管道不传游戏输入许可，不改变控制策略。Runtime 未运行或版本不兼容时显示原因，并保留手动地图/阵营。

旧 `--gsi-config <已有INI>` 和纯 CLI 全帧入口保留兼容；`--gsi-mode direct` 仍需显式选择独立接收端口，禁止占用 Runtime 端口。不要为了助手重新配置游戏、网络或防火墙。共享 GSI 不代表 NDI 并发和真实副机性能已经验收。

定位键是同一 `config.ini` 的可选 `[lineup] locate_virtual_key`，默认 `0` 未绑定。不得占用既有瞄准、启停、急停、扳机、释放或诊断键；现有配置读取器检查冲突。仅通过 Runtime 已有唯一输入监听转交定位按下边沿，不新增设备监听。恢复连接或启动时已按住的键不会伪造新边沿。功能需支持该协议的 Runtime 运行；键位由用户选择，手机定位按钮可独立使用。独立 `[lineup] throw_virtual_key` 同样默认 `0` 未绑定；仅新的按下边沿触发一次，长按不重复。启动助手不会自动写入这些绑定。

## 自动对准与单次投掷

选配方、人工就位、点击定位后，助手经独立同登录本地控制管道向 Runtime 发送新帧目标。原 GSI v2 管道继续只读、不传输出指令。Runtime 是唯一设备输出者；对准/投掷会话独占原仲裁器，先暂停并清理 Aim、急停、扳机、压枪和身法竞争输出，无法清理时明确退出。

对准要求同源时钟会话、实际 ROI 几何与接收代次一致、真实标定有效。Aim 的像素到鼠标计数比例不是本功能的量测标定，不会复用。每次小步后等待晚于发送完成加量测延迟的新源帧，连续三帧进入容差才显示已对准；丢帧、失焦、源变更、发散或超时撤销。计数每步最多12、最多40步、会话3秒是独立有限执行边界，不改用户 Aim 增益/速度。

已对准时按一次投掷键执行当前明确阶段配方。力度可设计左键、右键或双键；方向是玩家相对前/后/左/右，跳跃固定 **Space**，不发送鼠标下滚轮、不修改游戏 cfg。每阶段保存完整持有集合与持续时间，最后必须全部释放；空时间为未知，不能执行，示例/模拟时序不是通用 CS2 参数。双键50%是力度，不等于半程距离，具体时序与实际效果需逐配方验证。

KMBOX 协议已实现右键与 Space，并合并已有按钮/WASD状态；Win32/MAKCU不声明完整组合能力。整条动作在首个输入前检查后端能力、人工已持有键、完整时间和版本；不支持者整条拒绝，不把双键降左键或跳投降平投。后续阶段再次检查新增人工持有。仅清理本会话拥有的软件输入；Stop/退出/异常停止后续动作，但释放已经持有的攻击键可能立刻投出，不能视为安全取消，也不能靠释放后切武器保证撤销。

网页分别显示设计、模拟能力、当前后端能力和真实验证状态。协议 ACK 只说明按键发送确认，不证明准星移动、跳跃或手雷实际发生；仍需人工记录落点结果。本功能限本地练习研究，不提供规避 [Valve 官方输入自动化限制](https://www.counter-strike.net/newsentry/6500469346429600836) 的方法。

## 鼠标标定证据

同一 INI 的 `[lineup] calibration_file` 指向量测包内的 `calibration.json`，`calibration_context` 是用户记录的游戏灵敏度、缩放状态与版本等条件身份。两项默认空；软件无法自动证明游戏内灵敏度从未改变，条件改变应使用新的身份与量测。没有另建采集/网络配置。

量测清单需记录源名、后端、完整几何、条件身份、每轴至少两正两负的已知整数鼠标计数、目标误差前后变化、跨轴误差、观测延迟与原图对。工具不驱动设备；它检查并复制已有量测原图、计算 SHA-256、保留人工 `origin/reviewed` 声明。缺失声明默认为 `simulation/false`，模拟包永不成为生产标定。

```powershell
python scripts/build_lineup_calibration.py <量测清单.json> --check-only
python scripts/build_lineup_calibration.py <量测清单.json> --output <新的量测包目录>
```

Runtime重新校验原图 SHA、双轴双向覆盖、增益一致性、跨轴误差和延迟，增益从样本拟合，不读取手填默认增益。文件完整只能证明证据一致，不能替代真实量测与条件核对。用户须提供自己的真实量测包并设置对应路径；仓库不提供可直接用于真实输出的通用标定。量测工具、reader和拒绝路径的软件测试不替代真实量测。

## 待真实验证

实际使用前按自己的设备和正常使用时长，分别核对真实 ROI 参考、局部匹配精度/拒识、手机/LAN 延迟、NDI 并发、定位后对准、单键/双键/Space 组合、人工持有/中止清理及快捷键。所有真实输出由用户前台启动，软件测试不代替这些检查。
