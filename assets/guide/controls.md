## 安全与操作入口

> 物理鼠标输出默认关闭。任何真实输出都必须由用户在当轮前台明确授权、手动启动，并保留武装、
> 按住启用与急停门禁。请只在私有、离线或明确允许的环境中使用。

导航顺序为概览、检测、瞄准、辅助、采集、训练、调试、设置。键鼠后端、按键绑定和物理输出安全门
统一放在设置页；按键采集同时接受本机按键及已连接后端的有效监听快照，支持 KMBOX 鼠标侧键1/2。
捕获开始前已按住的键需要先释放再按下，输入失效或恢复首帧不会产生新绑定。

## 旋转跳与大跳

在辅助页的“身法”区开启总开关，旋转跳与大跳分别启用，可同时保留。默认上滚轮触发旋转跳、
下滚轮触发大跳；也可分别选择按键（Windows 虚拟键码 0–255，0 为未绑定、不触发）。
两项同时启用时必须使用不同触发，避免占用急停和其他功能键。游戏内须将所选按键或滚轮方向绑定跳跃，模块只监听这次输入，
不额外发送跳跃或蹲伏。触发前轻微左右移动鼠标选择首方向；使用最近 100 ms 的横向合计，
没有新方向时沿用上次，初始向左。动作开始后方向固定，期间滚轮不排队。

旋转跳执行一侧；大跳先首侧再反侧。鼠标向左选择 A 配合左转，鼠标向右选择 D 配合右转。
可调延时结束后临时屏蔽物理 W，结束、关闭或取消时释放模拟方向键并解除屏蔽。
不检查落地、垂直速度、梯子、武器、目标或其他模块状态；沿用应用输出许可与急停。

两模式分别保存角度和时长，大跳参数表示每侧。初值为旋转跳 90° / 300 ms、大跳每侧 15° / 150 ms、
触发后延时默认 0 ms，不再默认额外等待；这些仅供调试，并非已验证的最佳身法参数。运行中修改从下一次动作生效，关闭立即取消。
灵敏度默认 1.4，m_yaw 默认 0.022；鼠标计数按 `角度 / (灵敏度 × m_yaw)` 舍入换算，
表示未缩放视角估算，实际角度需游戏内核对。系统调度和设备发送耗时可能延长动作。

“兼容设置”可调整触发后延时、m_yaw、累计/相对报告与下滚极性。默认累计报告、下滚为正，尚未针对当前固件实机标定。
新配置分别保存 `spin_enabled/large_enabled`、`spin_trigger/large_trigger` 和对应 `*_virtual_key`；
旧 `mode` 单项配置迁移后保持原动作与下滚触发、保留显式延时，保存时移除旧 `mode`。
相对报告的重复字段会被忽略；固件若复带旧滚轮字段，仍可能漏报或误识别，须用实际输入核对。
设备发送失败会停止动作并显示错误；清理未确认时保留故障状态，需停机检查后重启。
当前实现与模拟设备测试不等同真实跳跃效果验收。

## Aim与界面调参

新建配置采用已接受的基线：平滑更新比例 `0.475`，X/Y 移动比例 `0.425/0.400`，
二维最大步长 `14`，延迟补偿开启、控制延迟 `15 ms`、最大补偿延迟 `44 ms`、
最大补偿距离 `15%`，预测关闭。已有配置保留用户保存值，不被默认值覆盖。

已有有效帧后的按键接管，及持续按住期间进入不同目标，
包括完全丢失后重新获目标，位置纠偏在首个有效样本建立起点，随后用 100 ms 有效控制时间
逐步恢复额度；不设置额外反应等待，量化后可能有零命令。空窗停发且不累计过渡时间。
按下时暂未确认目标也保留过渡起点，不因一帧空窗回到满幅冷启动。
同身份持续追踪和运动维持沿用原逻辑；源会话变化和 reset 清除接管历史。
生产组帧显式要求首次启动及完整重置后重新获准控制也缓入，防止重置抹掉按键边沿。
直接构造离线 AimFrame 的默认冷启动合同保持，不能用它替代生产初始化验收。
有可信独立背景且开启延迟补偿时，X轴执行位置纠偏归零后，仍允许源位置积分在已有运动维持额度内
补偿偏差；新增份额须沿当前运动或源误差方向，运动维持趋零时恢复原位置约束。
有效独立背景下，水平运动测量使用两侧边缘的中心位移，避免对称框宽变化使旧运动估计持续残留。
单边遮挡仍受检测与框内瞄准锚点的语义限制，不能据此推断目标真实中心；无背景时保留原模型回退。
100 ms 是工程候选过渡时间，不是人类反应阈值或转向完成承诺。当前没有逐目标死亡识别，
不能保证倒地动画期间停止跟随，目前仍由用户控制允许键停止。

“软化区范围 / %”是独立于原中心死区的可选弱跟随功能：0关闭，范围相对ROI短边半径。
“中心保留强度”默认0.20；每轴的位置纠偏从中心向软化边缘连续恢复到原强度。
X轴先追上当前目标的横向安全内窗（沿用身体瞄点范围比例），才逐渐启用软化；窗外与边界保持
追赶，离开内窗立即恢复，静态目标尚未追上时也如此。该判断使用当前匹配框，不是开火许可。
横向运动维持仅保留当前可信背景与目标共同位移支持的份额，停止、方向不符或缺少支持时仍弱化；
最终输出继续遵守原最大步长与接管缓入。不添加随机晃动，也不改扳机、急停或压枪。
开启软化时，Y从较远处接管会按首次有效偏差适度延长过渡；近处仍沿用原接管周期。
斜向纠偏使用同比二维限幅并协调双轴位置进度，远Y接管限制也同步收紧整个向量，减少一轴先到再补另一轴的折线。
当前背景和目标位移共同支持的运动维护独立保留；接近分轴死区时逐渐退出协调。
关闭软化或强度为1保留原分轴控制；不新增等待时间，无目标、观测空窗或压枪占用不积攒Y接管时间。
停止Runtime后修改；范围30%、保留0.20沿用。已接受场景作为体验基线，后续程序或参数变化按实际影响验收，不保证实机轨迹严格为直线。
旧配置缺键仍关闭；报告保存实际软化参数。接管完成后，软化区外沿用原追踪比例。

在普通界面停止 Runtime 后，可独立修改 X/Y 比例、平滑、死区、延迟和预测参数，保存后再启动。
两个开关可分别组合；关闭的功能保留参数供下次开启使用。最大补偿延迟应不小于控制延迟，
其他数值仍遵守界面和配置校验范围。自由调参不取消武装、按住启用和急停。

普通界面每次启动产生的 `cache/runtime/` 报告会保存本次实际 Aim 参数：JSON 的
`aim_config` 和 CSV 的同名注释可用于对应各次开关组合。报告不依赖随后修改的配置值。

预测关闭时，公有瞄点保持基础点。预测开启且世界运动来源可靠时，可独立产生提前点，
不要求同时开启延迟补偿；来源暂时失效后，已有提前量按原有速率回到当前基础点，恢复来源后
重新建立预测。控制延迟参数仍用于自身已发命令记账，不因两个开关关闭而失效。
四种组合的软件专项检查不代替人工闭环测试。

已建立的预测遇到短暂背景缺测时，仍按原速率回收提前量；同一目标及时恢复可信的同向观测后，
可接续已有预测，避免一帧缺口造成整段退零重建。恢复依赖当前观测，持续缺源、停止、反向或目标身份变化仍撤销旧资格。

展示三种模式时，按“基础追踪 → 加延迟补偿 → 再加移动预测”录制，并保持其他参数、目标运动和视角尽量一致。
延迟补偿作用于执行时刻的纠偏，不一定改变预览中的瞄点；移动预测的提前量随可信运动和预测时域变化，
数个像素的提前在全屏录像中可能不明显。最大预测距离是保护上限，不是固定提前量；
`predicted_gain` 用于丢失目标后的预测输出，不是正常移动提前的强度。不要为放大演示效果虚增控制延迟。
软化启用时，水平位置纠偏与残差积分按同一最终分配阶段结算，避免把软化削减的位置量记成反向积分。
评估时同时看目标基础点、预测点和实际准星，并检查停止与反向；三次不同输入的误差不能直接当作提升百分比。

## 阵营筛选

瞄准页可开启“自动排除友军”，依据本地玩家 GSI 身份、阵营和比赛阶段筛选 Aim 与自动扳机。
热身及每回合冻结准备阶段允许原已选全部类别；正式回合与回合结束只保留敌方类别。
本方 CT 时允许 T，本方 T 时允许 CT；半场/加时换边跟随 GSI 最新状态，不根据局数推测。
阶段未知、正式阶段阵营未知、过期或观战身份不符时暂停自动目标输出；换边及开局清除旧锁定与待发按钮，
可信状态恢复后重新选目标，不额外要求正常持键松开。原武器/焦点安全恢复规则仍适用。

通用配置默认关闭，必须按实际模型设置 `[team_filter]` 的 `ct_class_ids` / `t_class_ids`。
当前四类模型 `CT-boby,CT-head,T-boby,T-head` 对应 CT=0,1、T=2,3；切换其他模型需核对映射。
停机迁移可用 `scripts/set_team_filter.ps1 -ConfigPath <config.ini> -Enabled true -CtClassIds 0,1 -TClassIds 2,3`，仅修改该节并备份；关闭用 `-Enabled false`。
源端执行 `scripts/set_xen_gsi_realtime.ps1 -CfgPath <实际cfg路径> -IncludeTeamContext`
补充 `map` 和 `round` 订阅并重启游戏。GSI只识别本方，框的阵营仍由模型分类；不保证消除误分类误伤。
同阵营互相敌对的自由混战/特殊玩法应关闭此筛选。采集、自动标注和完整预览保留双方原始框，
友军不会因控制过滤而被采成空标注；准备/正式策略都与原瞄准类别选择取交集。

## HUD与H40策略

生产默认使用HUD线性运动模型制动；新配置及缺少策略键的旧配置采用 `[auto_stop] experimental_hud_model=true`。
显式 `false` 保留H40固定时长对照，保存/回读不会改回HUD；策略默认变化不会开启急停、循环、武装或物理输出。
需要切换现有配置时，停止Worker后使用 `scripts/set_hud_stop_strategy.ps1 -ConfigPath <config.ini路径> -Strategy HUD`；
回退用 `-Strategy H40`。脚本仅改策略键并备份原文件；不能靠恢复缺键的旧INI回退，因为缺键现在采用HUD。
每个Worker仅持有一个策略；逐轴计划按模型零交叉计算，释放后等待与目标、武器、许可、ACK、清理沿用原流程。
这部分自动控制是Xen适配，原HUD只有输入评估；模型完成不代表游戏实际停稳。
来源与适配区别见 [实机实验说明](../../assets/reference_assessment/HUD-EXPERIMENT.md)。
发布脚本 `scripts/publish_hud_experiment.ps1` 创建独立目录并保留当前配置和曲线；
`scripts/invoke_hud_stop_acceptance.ps1 -Mode Prepare` 生成前台任务，Launch必须用户亲自执行并提供物理确认参数。

## 自动急停

独立“辅助”菜单提供自动急停配置、允许键及会话暂停状态，配置保存到 `[auto_stop]`。
卡片只保留设置、当前会话与必要的阻断/故障提示；使用说明集中在本节，不常显运行统计和长段解释。
默认关闭，只支持 KMBOX NET。启用并运行后，WASD全部松开时按最后释放方向和当前反向保持时长轻点反方向，
无需允许键或目标；W+D松开W不动作，随后松开D才轻点A。反向释放后复用当前配置等待并自动结束，
重新按方向键立即撤销并归还。快捷键急停接管和清理期间的释放不叠加、不在归还后补发；
输入历史异常不推测松键。两种模式共用开关、源机焦点和安全许可，松键模式不授予扳机开火资格。
用于撤销的可信新按下，在清理成功且输入与许可仍有效后，可建立下一次真实松开的制动资格；
持续按住不提前制动，输入断流、代际变化或清理失败时不保留该资格。

Runtime 已提供 `request_auto_stop(request_id)` / `cancel_auto_stop(request_id)` 供后续自动扳机调用，
请求编号在会话中严格递增。自动扳机可请求制动；估算完成不等于已有独立停稳观察。
独立调度不依赖图像线程推进；暂停、End、输入异常与安全撤销仍取消并清理。
显式请求和反向制动过程最多 500 毫秒。持键急停首次准入要求准星进入配置人物的完整检测范围；
准入和保持共用本帧跟踪器的有效选中目标，仍保留已有确认帧数、获取范围和短暂丢失生命周期；
获取范围按本帧真实检测框与范围圆相交判断，近距大框不因基础瞄点在圆外而被排除；
丢失当前观测的预测轨迹仍按原瞄点判断范围，不用旧大框扩展资格。此规则不改变瞄点、类别/阵营筛选或开火条件。
不要求按住Aim键或产生鼠标命令。仅原始检测列表残留人物框、但已无有效选中目标时，不能新建或延续急停。
目标生命周期结束、处理失败或源观测过期即清理并归还移动。仅准星离框、离开扳机缩小区域或换方向键，
但仍有有效跟踪目标时，不作为目标消失处理。这不是死亡识别，也不消除检测器误报。
清理确认后，若允许键仍按住且目标恢复，重新核验并建立新的急停，
不要求松开允许键，也不沿用旧急停完成资格。
安装WASD屏蔽期间发生连续可信的换向，会先取消旧方向计划并确认归还，再按最新输入和新目标观测重新准入，
不因此要求松开允许键。可信连续输入中的A/D短暂重叠解除后，固定时序按当前方向重新执行完整制动，
不要求人工全松方向键；旧运动积分历史不会被补造。当前仍有相反方向同时按下时只保持屏蔽，解除冲突后重新核验。
松开允许键恢复移动，失焦及救援仍立即开始清理；信任故障或未知设备回执保持原有保护。
已在途设备应答可能推迟实际归还，不能视作硬实时保证。

允许键可与瞄准、自动扳机共用，不能使用 WASD、运行启停或安全急停键；按键采集支持本机及已连接后端，Esc 清空。
“释放急停按键”默认数字行 1–5 和 Q，任意一键取消接管，重复采集可追加；不能与 WASD 或允许键冲突。
设备监听失效时不能保证收到释放键，未知清理回执也不能当作已归还。会话暂停会取消并清理当前请求，恢复不重放旧请求。
释放清理成功后撤销旧制动资格，保留经过校验的真实输入连续性；急停不再要求松开允许键再按下。
焦点、武器上下文和输入恢复可信，释放键已松开且输出归还确认后，自动重新核验当前目标与方向，建立新的制动计划。
实际输入断流仍须重新取得可信历史；未知清理回执和输出故障继续阻断，不能用新目标或持续持键绕过。
释放键诊断仅在检测到边沿时记录配置键码与来源状态；日志代表监听报告，不单独证明用户真实按键。
“保持中（未制动）”表示方向冲突等条件下仅屏蔽方向输入，未执行反向制动，仍可能存在惯性滑行。
固定时序与旧运动模型分别核验输入：固定时序不依赖旧运动积分，但初始已持键、事件断流或换代仍须重新同步可信输入。
“预计完成”只表示设定的反向保持与释放后等待结束，不代表实测停稳或单独授予开火许可。
反向保持从按下协议确认起算，默认 40 ms、范围 1–200 ms；释放后等待从释放协议确认起算，默认 18 ms、范围 0–200 ms。
停止运行后修改并保存，下次启动生效；等待与武器冷却并行，不额外叠加完整点射间隔。
输出故障需检查设备和清理结果后停止重启；详细计数仍可在调试页“运行诊断”查看。
循环归还期间的连续同键监听报告保留原始接收时间，不会使下一轮退化为仅屏蔽；
每轮仍需重新完成反向制动与释放等待，不能以请求已创建代替完成资格。

键盘后端短事务与Aim串行；反向持有和释放后等待期间释放通道，Aim可继续追踪。
调试报告 `auto_stop.schema=2` 记录请求、清理、应答等待、释放调用迟到及 Aim 跳过次数；无测量项为 null。
模型结果仅为预计完成，`fire_permitted` 保持 false。实体屏蔽/归还、停稳效果与混合负载的实机结论
绑定各次验收的程序和配置；软件测试和协议 ACK 不替代新版实机验收。

持键急停仍需健康输入、源端焦点及50毫秒内有效源时钟图像；源桥接未启用时拒绝启动。已有输出故障不会因救援键自动解锁，需停止检查后重启。

## 自动扳机与移动循环

调试页“扳机调试”的“允许开枪”可关闭，保留检测、资格判断与急停联动调试，但不发送自动左键按下，
也不生成虚假开枪回执。该开关不阻止用户手动开枪；停止运行后修改，下次启动生效。

辅助页以自动急停、自动扳机、自动压枪三张卡片组织。自动扳机默认关闭，配置长按键并启用共享GSI识别后，
准星进入有效头部或身体矩形的设定范围即可判定，不额外叠加20ms驻留；框内仍不保证弹道命中。
“触发范围 / %”（`[trigger] range_percent`）以框中心等比缩放宽高，默认100%覆盖完整框，允许1%到100%，不扩展到框外。
首发不等待武器间隔，后续按住时长与相邻按下间隔统一读取当前武器的`weapon-timing`。
运行后仍需全局武装、新按键边沿、健康物理输入、新鲜源图像与源端焦点才能发出按钮命令。
“移动急停联动”只对移动或仍在制动的状态要求急停完成；原地且急停空闲时不等待无关的完成编号。
界面不再提供没有观察数据来源的严格停稳开关。移动联动使用当前制动完成与释放后等待，
与武器冷却并行，不重复申请急停或累计两份等待；许可取消或失效时撤销开火资格，估计与ACK不是实测移速。
默认HUD策略按逐轴模型估计动态制动，保留配置的释放后等待；显式设置
`experimental_hud_model=false` 时，H40对照使用反向保持与释放后等待（初始40ms/18ms）。
正常换弹、空弹和已识别非枪装备期间暂停，回枪恢复后重新核验目标与急停，不一律要求松开许可键；
焦点、输入、身份或ACK等安全信任中断仍需按提示恢复并重新武装。正常操作不注入测试中的100ms自动移动，
也不叠加测试循环的200ms射后等待；后续点射由武器间隔统一约束。反向保持和释放后等待仍可调整。
旧配置中的测试策略开关自动迁移，保留用户时长及各模块启停设置；保存时不再写入旧开关。
调试页的武器实验结果与辅助页组合运行的实机效果分别记录。

辅助页提供“移动→急停→点射循环”（`[auto_stop] cycle_enabled`，默认关闭）。用户持续按住方向键及同一个允许键：
首次按正常目标条件急停，点射按住到期且LEFT UP确认后解除WASD屏蔽，恢复用户真实方向键输入；下一轮重新屏蔽、
反向制动及点射。程序不代替用户按方向键。移动阶段利用当前武器点射间隔的剩余时间，下一次制动可占用冷却尾段，
两次DOWN仍不得短于武器间隔；每轮使用新的急停ID，至少经过一次已确认归还后的移动阶段。
开启循环会配置GSI自动选枪、共享武器资料、点射、估计急停联动和共用允许键；停止运行后编辑，配置GSI身份及源端连接后保存。
正常切枪、换弹和空弹退出当前轮并清理按钮/键盘责任；同一可信玩家重新就绪后，持续持键可重新核验目标与急停资格并开始新轮。
默认切枪键1–5/Q归还键盘后，松开切枪键即可重新核验，无需松开允许键。急停的取消、失焦或武器上下文中断也不再锁存人工重按门禁；条件恢复且清理确认后自动核验。
自动扳机自身的信任中断、单发和人工接管重武装规则独立保留。异常LEFT UP清理不启动下一轮，
未知释放回执不归还循环资格。有效新观测中候选丢失会立即抬键；UP确认且按键、焦点、输入与武器上下文仍有效时，
归还移动并等待候选恢复，无需松键重按；下一发重新取得急停资格，不能沿用旧ID。观测过期仍退出整个按住会话。
归还期间连续有效的同方向、改向、全松或短暂方向冲突均不要求重按允许键；后续按最新方向重新制动。丢包、换代或无效报告先撤销旧资格，取得可信输入前不恢复。
启用GSI时，Aim也在空弹、换弹或不可用武器期间暂停；恢复前清除旧目标与控制历史，发送前再次核验当前武器。启用源端焦点连接时，单独开启Aim也受源端焦点约束。
GSI只提供武器上下文，反向40ms/释放后18ms仍是可调估计时序；本功能的软件循环不证明实际停稳或点射效果。

自动扳机快捷键可同时加入瞄准输出的多键绑定，按住时同时启用两项功能。扳机只判断开火条件和控制左键，
不会修正准星位置；准星追踪由Aim负责。两者当前独立选择目标和区域，共键不保证瞄准对象与开火候选身份相同。
Aim仅发送计算时与发送前都获得许可的帧；计算途中按下快捷键会从下一帧生效，松键仍在发送前拦截。
急停的反向持有、释放后等待不占共享输出通道；实际键盘事务与Aim位移仍串行执行。
Aim在计算前有界等待短事务完成，再按实际控制时刻计算，不因正常辅助等待直接丢弃命令；
安全撤销、共享故障或超过后端事务等待预算仍会停止输出。

### 随机开火时序

辅助页的“随机开火时序”是独立开关，默认关闭。开启后，每次候选准入随机等待45–65ms，
LEFT UP确认后保留120–180ms松开间隔；在合法区间内加入最多±15ms条件扰动，最终不越界。
按下等待与急停资格、松开冷却并行，不改变武器按住时长或缩短武器最小DOWN间隔。
因此实际开火可能因目标、武器或急停条件更晚；抽样值不是Windows/设备物理时刻保证。
UP确认后立即归还方向，仅将下次制动准入对齐到松开间隔；HUD模型、18ms制动参数保持。
松键、End、失焦和故障清理不等待随机期限。报告记录本次抽样值，关闭开关恢复固定时序。

### 候选、武器和共享输出

自动扳机与急停复用唯一 KMBOX owner；失焦、取消、帧过期或未知回执停止新动作并处理软件左键释放。
正常候选变化会中止本发；软件左键释放已确认、会话许可仍有效且无人按住物理左键时，归还方向键。
下一发必须取得新候选和新的完整制动资格，不复用上一目标的急停编号；人工接管仍优先处理。
扳机局部图像失效或人工接管未获准时，只清理本次开火，不擅自取消仍安全按住的独立急停；
独立急停仍自行处理松键、失焦、武器上下文失效及全局安全撤销。图像恢复后仍遵守原点射冷却和新帧条件。
启用 GSI 时，正常切枪、换弹或空弹清除旧驻留并释放已持按钮；可信状态恢复后可持续持键，使用新目标、新武器时序与新的急停资格。
数据过期、未知状态、身份异常、自身死亡以及失焦等信任中断仍需健康松键再按下。普通心跳不会反复取消。扳机、急停与压枪共用同一个GSI接收器，不再提供独立武器手选或节奏开关。
GSI、弹道和共享武器资料统一使用 `assets/weapon_catalog.inc` 的名称目录：内部沿用稳定ID，界面统一显示名称。
例如 `weapon_m4a1` 为M4A4，`weapon_m4a1_silencer` 为M4A1-S；旧 `m4a1.csv` 的曲线身份与文件名保留，导入后武器ID为 `m4a1_s`。
支持34种GSI枪械名称，其中G3SG1没有共享点射资料，R8只留档且禁用；识别成功不会补造弹道或时序。
调试页“弹道工具”的共享武器资料编辑器管理33种武器的按住时长和按下间隔，关闭压枪也能使用。
扳机直接按共享GSI选枪；未知/禁用资料不沿用上一把。默认沙鹰60/600ms、AK与M4为60/300ms；R8仅留档。
点射资料不缩放压枪弹道。按住从DOWN协议ACK计时，间隔从DOWN提交计时；UP未确认不发送下一DOWN，调度迟到不补发。
旧INI中的独立节奏开关、手选、扳机延迟/模式/按住/间隔和头身缩放已停用，保存时移除，现有weapon-timing文件不改写。
资料保存在独立`cache/recoil/weapon-timing.json`，默认路径缺失时使用内置人工采集表；自定义路径须先保存。
停止运行后编辑、保存资料及全局配置，下次启动读取固定版本；启动后无文件轮询或新增线程，武器未变时复用所选项。
释放清理只把实际后端调用计入尝试次数，争锁单独受清理截止时间限制。按钮报告保留后端完成与
协议 ACK 原始时刻；压枪的软件触发起点仍是命令估计，不能当作游戏逐弹时间。
Debug 独立保存扳机有界事件历史、压枪拒绝原因及按 Aim/扳机/压枪分类的仲裁累计计数；普通 Log
关闭不影响这些执行证据。点射执行报告schema 2保留武器/版本、估计请求id、实际提交间隔和ACK到UP提交时长；
断档和不完整事件保留null，次数不代表子弹数。换枪取消的UP仍记录原发参数。
覆盖缺口显式记录，模型重载报告不重复导出已记录的扳机事件。
Release 专项与假设备测试不替代真实游戏/设备验收；真实输入只由用户前台触发。

## 双机焦点与时钟

使用 NDI 时，自动急停需要源机 `XenClockSource.exe` 持续提供时钟同步；源焦点桥接与时钟服务是两个进程。
源机时钟服务未启动会使源帧时间无效，急停不会发起制动。辅助页卡片顶部显示会话与阻断原因，
可据此区分未按允许键、源焦点不可用、时钟未同步及目标条件未满足。

双机焦点由 `xen_source_context.exe` 提供：源机显式指定 `--enable --host <源机绑定地址>
--port <端口> --process <游戏可执行文件名> --ttl-ms 200`，主程序设置页填写对应地址、端口和进程名。
两端认证使用环境变量 `XEN_SOURCE_CONTEXT_TOKEN`（至少 32 字节），不写入 INI、命令行或报告。
程序不会自动运行源端工具；游戏持续发送数据也不等于游戏处于前台。该工具只提供焦点事实。
部署工具 `scripts/install_source_context_credential.ps1` 从标准输入安装受 ACL 限制的 DPAPI 密文；
`scripts/start_source_context_session.ps1` 仅向子进程环境传入认证，支持源服务、用户启动 Launcher 与只读 Probe。
Source 模式可传 `-ClockBindUrl udp://<源机地址>:5011`，同时启动或复用同目录的只读 `XenClockSource.exe`，避免焦点正常但NDI缺少源时钟。该服务不发送设备输入。
重复启动相同源服务时，脚本验证端点、进程参数和当前凭据后复用现有实例；其他端口占用会明确报错，不结束现有进程。
已配对的辅机包使用 `Start-Xen.cmd` 启动，避免直接打开 Launcher 时缺少认证环境；主机源服务须在游戏所在交互会话运行。

## 弹道配置与活动版本

压枪默认关闭，采用共享 GSI 自动识别武器并精确匹配已校准弹道。普通压枪无额外许可键，旧INI键值不再阻断运行；

调试页“弹道工具 → 压枪校准配置”仅保留曲线目录和游戏灵敏度，曲线编辑、校准及活动版本选择也在该页。
游戏版本和适用条件不再必填或参与运行匹配，旧记录可作为历史元数据保留；输入路径固定KMBOX NET。
普通压枪不依赖混合图像有效期、检测成功或源视频时钟；Aim和扳机仍保留各自视觉准入。启用失败只列出实际缺项。

GSI 只用于武器、弹药及换弹上下文，不能提供弹道曲线、逐发时钟或焦点证明。

新采集候选继续使用显式“时间—累计 counts”曲线；已确认旧17曲线可另存为schema3离散事件，保留首步等待、绝对计划时间及逐步浮点余量取整。可追溯导入入口见
[本地导入说明](../../assets/recoil/README.md)；输出是待校准候选，不会自动激活。
在调试页弹道工具中加载候选，常用只调横向/纵向强度；起压偏移和时间伸缩折叠显示。
也可直接编辑节点、撤销/重做并对比曲线。保存始终生成新版本；完成校准并填写实际证据后，
可显式发布活动版本，原活动版本支持回退。固定版本覆盖已移除，旧INI的use_trial/trial_file停用且不再保存；
运行时只使用对应武器的明确活动版本，仍检查已校准状态、模式、KMBOX输入路径与实际灵敏度。运行期间不热换曲线。
新配置的曲线目录为 `cache/recoil/profiles`；旧配置显式填写的目录保留，不自动搬移旧曲线及其证据。

## 弹道采集与验证

弹道采集按 GSI 弹药减少量停止，并在松键后核对本次发数；少发、多发、计数缺失或射击中回退均不能用于训练，失败不会自动补枪。
新采集默认使用游戏内“跟随后坐力”准星，首组最多5发：设置不透明洋红色（RGB255/0/255）、关闭轮廓，仅保留画面中2–5像素的实心中心点，再点击“重新标定并采集”。
算法记录准星相对背景的轨迹，不使用弹孔；准星多解、缺失或裁边时停止，独立四向标定同时检查准星位置与视频响应延迟，避免直接在松键接收时刻截断末发。此对齐仍有不确定性，不代表逐发曝光或物理效果已验证。

调试页弹道工具提供“采集新弹道”和“验证已有弹道”两个常用入口，曲线列表自动读取。
先停止Runtime，保持既有KMBOX连接，在调试页启用并保存一个不冲突的测试键（例如未占用的F6）。
填写实际游戏灵敏度，选择武器和本次发数。采集入口在缺少标定时先准备画面标定；回游戏对准静止且有纹理的靶面，按测试键后松开。
标定只执行有限的两轴位移，不开枪；成功后自动准备采集，再按同一键执行一组自动扫射，无需返回菜单重新准备。
标定和初始采集各只消费一次准备许可；一组有效采集已生成候选后，先核对并保存，不再用热键反复重采初始发数。
标定或画面几何失效并提示重新标定时，会清除该武器失效的标定引用；普通背景匹配失败只要求重新对准，保留几何与灵敏度仍有效的标定。
也可直接点击“重新标定并采集”；标定成功后只准备下一组，仍须你回游戏再次按测试键。
纹理或匹配不足时先换静止、细节清晰的靶面；只有实际位移接近观测边缘才建议减少本阶段发数，此时仍可复用有效标定。
已有曲线统一从“测试曲线”选择，验证直接使用该选中对象，无需再次选择文件。
外部JSON通过文件选择入口导入，导入后加入同一曲线列表、自动选中并准备验证。
结构有效的IMPORTED候选也可用于本次有界测试；原文件和生产校准资格不变，取消文件选择保留当前曲线。
直接验证不依赖画面、纹理、画面标定或图像范围检查；需要采集优化数据时启用“记录优化数据”，缺少标定会先引导标定。
标定动作完成不等于标定通过；失败后再次按键保留具体原因。已有候选可关闭“记录优化数据”，点击“验证已有弹道”重新准备人工观察；需要优化数据时再完成有效标定。
每按一次只执行一组，忙碌不排队；紧急停止键、失焦和超限均停止，采集/优化测量还会在观测失配时停止。
尚未就绪时界面分别提示测试键/左键/WASD未释放、源焦点、GSI武器或图像的具体原因。常规Aim/扳机不同时运行。
“等待源焦点状态”表示尚未进入射击/补偿阶段；先在游戏主机同一交互会话运行既有源焦点服务，再回游戏前台测试。
源焦点服务与GSI、时钟服务相互独立；只打开游戏或收到GSI武器状态并不代表焦点服务已经运行。

没有曲线也能采集：先测量画面位移与设备counts的映射，再从准星相对背景的运动生成候选；关闭“跟随后坐力准星采集”可保留原背景流程。
它不把准星动画或GSI弹药包当作真实逐发弹着；保存的候选仍未校准。查看本组画面后，点击“画面已核对：保存候选并准备测试”，
即可载入候选并准备下一次测试；有标定的测试结果经人工核对后可加入优化，无标定验证不生成训练数据。
采集图像等比限制至960×540、最多约30帧/秒，保留实际源/接收时间与几何，不伪造固定采样时序。
画面配置、实际尺寸或灵敏度变化后重新标定。背景接近观测范围边界或失配的数据不参与训练。

“本次发数”和折叠设置中的“每阶段追加发数”可按武器调整并保存，后坐力大的武器可从1至2发开始。
目标发数由GSI弹药变化辅助停止，并有最长扫射时限；GSI延迟可能导致超发，未知或不符目标的组只保留原始记录。
一组有效初始采集即可生成候选；保存后先实测，满意可直接追加。需要优化时，同一曲线累积三组训练和两组独立验证画面，点击优化，程序另存候选、载入并准备复测，禁止重复消费验证数据。
常显的“优化与阶段推进”展示组数和阶段目标。本阶段实际复测满意后，点击锁定前段并追加，自动准备新增目标的测量测试，仍须用户回游戏按键；缺少有效标定时先标定，再准备该测试。
优化只修改锁定点之后：已有时域有限微调，超出旧末端的时域按测量建立。达到整组发数后停止追加，可解除锁定做整体微调。五组优化数据不是生成初始候选或人工推进的前置条件，失败组不计入。
此时间域优化使用独立画面标定，不冒充下述高级数据集的射击响应H、真实相位或校准证据；离线预测改善仍需实测。
结果保留在 `cache/recoil/workflow`。展开“载入以前的采集”，按当前武器选择发数、采集类型和独立记录，再点“载入所选记录”，无需复制路径；新记录可点刷新，重新打开程序仍可选择。
载入恢复该组对应发数，只读取结果，仍须人工核对后保存候选或加入优化数据。高级路径导入继续保留，失败和不可用的测量不列入常用历史列表；高级编辑与旧数据集优化保持折叠。
背景配准按完整模板和两侧中点采样的真实图像支撑确定搜索范围，不再按模板尺寸30%截断；拒绝多解纹理、真实边界外推和不可靠残差。标定仍使用既有显式64像素范围，有效v3标定可继续使用。
残差在两侧固定3×3、σ0.5预滤波后对称插值到中点空间核对，降低文字边缘对采样相位的敏感性；原图相关匹配、歧义拒绝和位移范围保持独立，原始残差也保留诊断。
滤波只使用具有真实邻域的像素。升级配准版本后须重新标定，旧标定不能直接用于采集；标定任一步ACK后前后画面完全相同时立即停止并说明方向，不自动补发。
背景匹配失败时另存首个失配画面及参考帧引用，用于排查首枪变化；该诊断图不参与曲线生成或优化训练。

### 追加阶段的数据合同

每组核对后加入优化数据；累计三组训练和两组独立验证，点击“优化本阶段并载入候选”后才会生成八发候选。
载入历史记录只恢复测量和阶段，不会自动训练或更新测试曲线；同阶段载入保留已加入组与前段锁定。
优化区分已有段微调和新增段建立：已有时域每轴修正仍受预算限制；超出旧曲线末端的部分，
按三组测量相对旧末端的残差变化建立并连续连接，锁定前段保持。新段只到五组共同观测末端，
独立验证须同时通过整体、新段及末端的预测残差改善；通过后仍须人工复测。
更新程序不会重写已经保存的候选。旧版生成的追加不足曲线，应回到此前满意的短基线重新追加；
已经消费的五组仍保留作诊断，生产新候选须使用新的独立采集，不能清空用途登记后复用。
源端 Xen GSI 配置可用 `scripts/set_xen_gsi_realtime.ps1 -CfgPath <gamestate_integration_xen.cfg完整路径>`
取消主动缓冲和节流（buffer/throttle 均为 0.0）；脚本保留其他配置和原文件备份，支持 `-WhatIf`。
修改后重启游戏再由用户前台采集，以排除旧配置缓存。GSI 仍有传输和调度延迟，接收计数不代表精确逐发时刻。

## 混合输出与人工接管

独立压枪模式停止 Aim 的设备位移；混合模式在压枪弹序期间由Recoil独占Y，Aim继续X，退出后清理Y执行记忆再恢复。已确认压枪位移仍记入外部运动账本。
两者保留共享输出互斥；Aim沿用单帧二维步长上限，不因启用压枪追加滚动累计节流，旧budget_window_ms仅保留配置兼容。
压枪正常锁忙保留未发送事件，1ms可中断轮询逐步重试，不跳步或批量补发。
自动扳机遇到暂时锁忙保留同一待发命令并复核最新目标与许可；目标、图像或许可失效即撤销，未调用后端的按下不伪造抬键。
单次点射已确认按下后，原目标仍唯一连续匹配、仅暂时离开触发范围时，完成既定按住时长再归还移动；不延长该时长，也不允许在范围外开始下一枪。目标丢失、匹配歧义、换目标、图像过期或许可撤销仍立即结束本发。
近距离人物框经检测器裁剪后可以贴住ROI边界；扳机按该有效框判断范围，不因贴边而拒绝，实际越界和退化框仍拒绝。
实体左键与仍有效的自动扳机会话都可建立估计起点。已确认的死亡、换弹、空弹或合法换枪恢复时，旧离散弹道从首步建立新会话；失焦、输入故障、数据过期或身份异常仍须健康释放，未知回执锁存故障且不重发。
自动点射期间人工按下左键优先接管，压枪以该人工上升沿从第一发重新开始，持续按住不重复重置。
扳机清理自己的软件按下后不再点射；人工松开后须松开并重新按住扳机键才能重新武装。
已完成的急停在人工接管后继续保持，不因左键或激活键松开而归还；目标消失、换弹、自身死亡、
武器上下文失效或现有安全撤销时释放。目标存在与准星是否在框内分开判断。
软件释放与物理长按在设备端是否无瞬间断射，须针对当前固件实测，客户端ACK不构成该证明。
曲线耗尽且持续按住时不循环。旧离散计划不因20ms软件相位预算中断，后端单事务超时与未知回执保护仍有效。

## 独立校准与离线优化

未校准候选通过编辑器“校准此版本”准备独立会话：选定已保存版本，填写已保存配置路径、
新目录及一次性环境/预算，准备后复制完整前台命令。先退出应用释放设备，再由用户执行该命令。
准备不启动设备；独立工具仅接受人工保持键和实体左键，不启动 Aim、自动扳机或自动急停。
保持键与取消键必须不同且不能使用左键或 WASD，保持键可用鼠标侧键。每次准备绑定曲线与配置摘要，只允许一次弹序；
取消、超时、上下文失效或未知回执后不能续跑。命令相位预算只约束发送时限，不代表实测校准结果。

命令行离线入口为 `xen_recoil_calibration.exe prepare PROFILE CONFIG REQUEST NEW_DIR` 和
`xen_recoil_calibration.exe inspect SESSION`。`REQUEST` JSON 包含 `environment`
（`weapon_id`, `game_build`, `input_path`, `conditions`, `sensitivity`）、`hold_virtual_key`、
`cancel_virtual_key` 和 `limits`。后者必须明确填写 `max_firing_sessions`（仅 1）、
`max_session_duration_ms`、`max_firing_duration_ms`、`max_sent_l1_counts`、`max_command_l1_counts`、
`rolling_window_ms`、`rolling_window_counts`、`command_phase_budget_ms`。
生成目录中的 `TASK.md` 给出唯一绑定命令；不要自行省略物理输出标志和确认串。
结果保存原候选、预算和原始执行记录，`calibration_result` 与 `physical_acceptance` 保持空值；
人工完成真实测量后再另存校准版本并显式发布。

正常应用开启压枪后，后台将每次射击的 BEGIN/COMMAND/END 独立归档至
`cache/runtime/<采集Run>-recoil-batches`。这不依赖普通 Log 等级，模型重载仍沿用同一采集身份。
单批上限 32768 条记录、16 MiB；单会话上限 4096 个文件、256 MiB。覆盖、缺边界、写入失败和
超限会显式标记，调试页和 Debug 报告显示归档状态，辅助页保留错误摘要。后台磁盘写入不占用设备输出锁。

“弹道自动优化”独立于实时输出。导入已结束的 Run 和测量后，模块检查环境/曲线/回执时序、
响应标定是否可辨识，再用稳健拟合生成有界候选，并显示留出数据的离线预测对比。
候选不会覆盖活动版；预测改善不等于新候选已取得实测改善。保留旧 Debug `recoil.schema1` 兼容，
新的逐次射击文件使用 `recoil.schema2`，包含会话起点、完整边界、逐命令回执与实际曲线版本。
数据集仅接收自然结束、完整且已校准的批次；同一采集 Run 不能拆作独立留出。
未校准候选的原始校准记录不能直接进入优化拟合，命令相位预算也不能冒充已验证相位容差。
UI 和 CLI 共用生产执行器的软件回放，记录模拟步长、相位预算、命令量化与尾部、取消和异常回执检查。
回放不会授予校准资格，也未验证 Worker 累计/滚动预算或物理效果；候选仍须真实校准和人工验收。

命令行也可独立分析：

```powershell
python -X utf8 scripts/build_recoil_dataset.py <人工测量清单manifest.json> <新的数据集.json>
build/nvidia/Release/xen_recoil_tuner.exe optimize <数据集.json> <基线profile.json> <新结果目录> <优化代数> <新版本号>
```

测量清单格式见 `python -X utf8 scripts/build_recoil_dataset.py --help`。脚本从 Debug 提取真实回执及
曲线身份，只接收用户明确提供的残差、噪声与测量时间；缺记录或未知回执不进入拟合。
在正式包中，改用 `tools/recoil/build_recoil_dataset.py` 和所选 `runtimes/<provider>/xen_recoil_tuner.exe`，
并把新结果目录放在 `cache/recoil/tuning` 下；命令不依赖源码目录。
UI 和 CLI 共用当前用户 `%LOCALAPPDATA%/Xen/recoil-tuner-usage-v1` 用途记录；已用于拟合、
响应标定或留出分析的数据不能重新作为独立留出。新一轮优化需新的测量资料。
成功时，新结果目录根部另存可由编辑器加载的 `SCHEMA_VALID` 弹道版本，分析报告位于
`analysis` 子目录。候选清除旧校准证据，需要重新校准后显式发布；命令不会修改活动版本。
