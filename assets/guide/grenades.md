# OBS 道具菜单与找点

日常统一使用主机 [OBS 道具插件](../../tools/obs_grenade_overlay/README.md)。辅机 Xen 和 Runtime 保持运行，地图及本地阵营跟随 GSI；手机选择入口和语音助手已移除。HTTP 5015 用作 OBS 与辅机之间的内部接口，不再提供手机首页。

## 日常使用

1. 辅机启用道具辅助按键并保存。默认上键找点、下键投掷、左键取消，End 保留全局急停。Runtime 要处于运行状态，才能复用已有画面而不重新连接 NDI。
2. 游戏中按小键盘右键打开菜单，再按一次隐藏；NumLock 关闭时用方向右，开启时用小键盘 6。菜单居中，默认约 800×430 像素，采用圆角暗色、约 92% 不透明背景，可直接鼠标点选和滚动。
3. 默认按站位分组，也可按落点查找。选择 1 号位后查看 VIP 烟、B小烟等瞄点；出生点共用一张站位图。辅机完成载入后，菜单消失并将焦点交还游戏，右上角显示当前方案的站位与瞄点参考。
4. 自己拿出对应道具、站到参考位置，把视角大致转到瞄点附近，再按上键找点。找点短时借用 Runtime 已有的 320×320 原始 ROI，完成或取消后归还；采集和检测不重启。
5. 找点会继续细调剩余小偏差，对齐完成后参考卡隐藏，不播放成功提示音。按下键按相同精度复核当前画面并执行原方案动作，不再移动瞄角；按左键取消本次操作。换方案、换地图或重采图片后重新找点。

参考卡只在人工重新点选后显示，对齐、投掷或取消后持续隐藏；重启、重连和 F10 换图不重播旧提示。OBS 原有中央 320×320 NDI 输出保持原样。菜单和参考卡均请求 Windows 系统截图排除；F10 另主动隐藏插件窗口后再采原图。

## F10 自动制作与发送

不再单独启动制作工具。先人工试投，确认能到目标后恢复原站位和正确瞄角，关闭游戏控制台，按 F10。OBS 插件隐藏菜单和卡片，启动内部单次采集作业，读取辅机实际选中方案、采当前全屏、生成 320×320 映射、按短名打包并发送。F10 本身即为人工试投确认，不再弹二次确认。

T1～T5 共用用户提供的出生点图，各自站位在显示层标记；其他站位图片放在主机资源目录 `standing/<方案文件stem>.png`。名称如“T1 VIP烟”“T1 B小烟”，动作时序不因命名或截图而改变。Runtime 可保持运行；制作时不要同时找点或投掷。

采集完成后在主机显示短通知。发送成功后插件读取新的资源版本，下一次查看即可使用新图；当前可见参考也会随版本刷新。重复采集保留备份并撤销旧对齐结果。发送未确认时保留本地资源和恢复记录，通知显示原因，不把本地保存当成辅机已更新。

插件安装时填写主机已有 Python 路径，只使用标准库，不需要语音模型。在 OBS“工具 → Xen 道具提示”可修改采集 Python、本地资源目录和辅机共享目录。

正式方案在 `cache/grenade/plans`；参考资源在 `cache/grenade/references/<方案stem>/`，包含 `standing.png`、`aim.png`、`reference.json`；短名包位于 `cache/grenade/packages/<地图>/`。原图不改写，站位圈、ROI 和瞄点由 OBS 显示层绘制。

## 人工试投与验证

制作调试入口仍为辅机“调试 → 道具测试”。F11 直接执行当前方案原动作，不要求参考图或先找点；运行中的 Runtime 会短时交接输出。上键/下键用于图片找点和投掷。首次坐标复位可沿用“复制定位指令”；F10 图须来自恢复后的正确画面。

方案库与身法库分开，身法仍在 `cache/movement/plans`。已确认的投掷动作参数保持。构建、合成图回归、双机文件同步和真实落点分别验证；新菜单的实际焦点返回、游戏中点选及 F10 全流程仍需实机观察，不能由编译或接口回执替代。
