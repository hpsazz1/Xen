# OBS 道具菜单与找点

日常统一使用主机 [OBS 道具插件](../../tools/obs_grenade_overlay/README.md)。辅机 Xen 和 Runtime 保持运行，地图及本地阵营跟随 GSI；手机选择入口和语音助手已移除。HTTP 5015 用作 OBS 与辅机之间的内部接口，不再提供手机首页。

## 日常使用

1. 辅机启用道具辅助按键并保存。默认上键找点、下键投掷、左键取消，End 保留全局急停。Runtime 要处于运行状态，才能复用已有画面而不重新连接 NDI。
2. 游戏中按小键盘右键打开菜单，再按一次隐藏；NumLock 关闭时用方向右，开启时用小键盘 6。菜单居中，默认约 800×430 像素，采用圆角暗色、约 92% 不透明背景，可直接鼠标点选和滚动。
3. 默认按站位分组，也可按落点查找。选择 1 号位后查看 VIP 烟、B小烟等瞄点；出生点共用一张站位图。辅机完成载入后，菜单消失并将焦点交还游戏，右上角显示当前方案的站位与瞄点参考。
4. 自己拿出对应道具、站到参考位置，把视角大致转到瞄点附近，再按上键找点。找点短时借用 Runtime 已有的 320×320 原始 ROI，完成或取消后归还；采集和检测不重启。
5. 找点会继续细调剩余小偏差；接近瞄点时用共同纹理精修亚像素位移，避免斜向纹理让算法提前判定完成。天空、天线等稀疏画面在常用区域不够时，会补查ROI内其他区域，保持相同精度，不需要因算法更新重新采图。对齐完成后参考卡隐藏，不播放成功提示音。按下键按相同精度复核当前画面并执行原方案动作，不再移动瞄角；按左键取消本次操作。换方案、换地图或重采图片后重新找点。

偶发的网络时间信息异常帧会自动跳过，等后续正常画面继续本次找点；异常帧期间不移动鼠标，不要求手动校时。持续没有可用画面时，本次找点会结束，可恢复画面后重新按上键。

参考卡只在人工重新点选后显示，对齐、投掷或取消后持续隐藏；重启、重连和换图不重播旧提示。OBS 原有中央 320×320 NDI 输出保持原样。菜单和参考卡均请求 Windows 系统截图排除；F9/F10还会主动隐藏插件窗口后再采原图。

## 独立采图与自动发送

不再单独启动制作工具。F9只采站位图，F10只采瞄点图；两者无先后顺序要求，互不覆盖，各自自动保存并同步。只有站位图时可看站位参考；只有瞄点图时也能找点。

F10仍在人工试投成功、恢复原站位和正确瞄角、关闭游戏控制台后触发。插件读取辅机实际选中方案，采当前全屏并生成320×320映射，按方案短名打包发送；F10本身即为试投确认，不弹二次确认。F9可独立拍下便于辨认站位的画面，无需先试投，不改变F10的图片和确认记录。修改方案后只按F9会保留旧瞄点图原来的方案关联；F10才更新瞄点图及其关联。

出生点按同地图、同阵营共用站位图：选中T1、T2或CT1这类编号方案，按一次F9采俯视图，自动同步到该地图同阵营全部出生点方案；各方案的瞄点图继续独立。以后新增同组方案，F10会复用已有站位图，普通点位仍单独采F9。用户俯视图不套旧图坐标标记；未拍新图时，Mirage T1～T5可沿用原上传图。名称如“T1 VIP烟”“T1 B小烟”，动作时序不因命名或截图而改变。Runtime可保持运行；制作时不要同时找点或投掷。

采集完成后在主机显示短通知。发送成功后插件读取新的资源版本，下一次查看即可使用新图；当前可见参考也会随版本刷新。重复采集保留备份并撤销旧对齐结果。发送未确认时保留本地资源和恢复记录，通知显示原因，不把本地保存当成辅机已更新。

插件安装时填写主机已有 Python 路径，只使用标准库，不需要语音模型。在 OBS“工具 → Xen 道具提示”可修改采集 Python、本地资源目录和辅机共享目录。

路径均相对于现役程序目录：正式方案在 `cache/grenade/plans`；参考资源在 `cache/grenade/references/<方案stem>/`，`reference.json`只登记已采的`standing.png`、`aim.png`；短名包位于`cache/grenade/packages/<地图>/`。原图不改写，站位圈、ROI和瞄点由OBS显示层绘制。

## 录入自己的道具

在辅机“调试 → 道具测试”填写道具名称，通过“地图”和“阵营”下拉选择所属地图及T/CT。新草稿默认采用有效GSI，手动选择和已保存方案不会随游戏换图、换边被改写；“使用当前地图与阵营”可主动重新填入GSI。地图列表包含全部预置地图、GSI当前地图和方案库已有地图；其他地图可选“自定义地图”填写其标识（仅小写字母、数字及下划线，最多83字节，不填写路径）。无GSI时也可手动录入保存，实际F9/F10仍核对当前游戏地图及本地阵营。

名称可自由填写，例如“T垃圾桶左 拱门烟”，不再要求T后接数字。阵营独立保存，旧方案仍兼容原命名；为旧方案补存相同阵营不需要重新采图，实际改了地图、阵营或动作仍须重新采集对应瞄点。把完整`setpos ...;setang ...`粘到唯一的“定位与瞄角指令”输入框，保留复制按钮。道具名称兼作点位名称，不再重复填写点位。“投掷动作”下拉可套用左键原地、左键跳投、W跳投、蹲跳投、蹲W跳投、左右双键W跳投这六套现有时序；选择只改草稿的动作和按键屏蔽，保留名称、地图、阵营、点位与坐标，不自动保存或执行。下方动作明细可继续微调。

“道具方案”按地图、T站位编号、CT站位编号、其他点位排列；编号和名称中的数字按自然顺序（T1、T2、…、T10），同名备用瞄角放在原方案后。选定地图后只显示道具短名，文件路径放在悬浮提示中；全部地图时额外显示所属地图。旧文件的点位资料和命令附注仍保留，身法编辑器不受影响。

坐标和截图不能自动确定投法，需按实际动作选择预设并用F11试投。新方案点击“保存方案”；基于旧方案改新道具时使用“另存新方案”。保存并选中对应方案后，F9/F10自动绑定其名称和地图，不需再次填写。瞄点图在试投成功后采，站位图可先采或后采。

## 人工试投与验证

制作调试入口仍为辅机“调试 → 道具测试”。F11 直接执行当前方案原动作，不要求参考图或先找点；运行中的 Runtime 会短时交接输出。上键/下键用于图片找点和投掷。首次坐标复位可沿用“复制定位指令”；F10 图须来自恢复后的正确画面。

方案库与身法库分开，身法仍在 `cache/movement/plans`。已确认的投掷动作参数保持。构建、合成图回归、双机文件同步和真实落点分别验证；新菜单的实际焦点返回、游戏中点选及 F9/F10 全流程仍需实机观察，不能由编译或接口回执替代。
