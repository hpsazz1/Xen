# HUD运动模型实验版

AUTO-STOP-HUD-EXPERIMENT-001。用户2026-09-22明确要求整合可前台实机比较版本，独立包保留原版。

## 算法与适配

基础来源为cs-match-hud固定提交e632605f8b6c20ac5ab8ac3284e4fdc33735d431的Basic运动估计：逐轴加速5.5/s、自然减速2.5/s、反向减速14/s，逐轴限制±1；tiny残差沿原模型5.5/s分支。完整MIT许可随包提供。

原项目只有观测评分，没有自动控制。本实验新增Xen控制适配：先零报告确认，再按模型残余方向反向；DOWN协议ACK时计算每轴零交叉截止时间并分别释放。长持单轴最多约71.43ms；短持更短。ACK前按原有效输入积分，ACK后才切换虚拟输入，迟到释放保留模型残差，不强制归零。

反向全部UP ACK后仍使用原配置18ms等待；这是Xen原等待，**不是**把HUD的DOWN+18ms采样延迟当停稳证据。HUD的0.34、蹲下和起步评分宽限不授予生产开火许可。最终仍为ESTIMATED，实际发火由原扳机目标、武器、许可、时效和清理流程决定。

保持Xen同轴冲突保护，不复制HUD评分的last-pressed-wins为物理输出规则。冲突解除或健康清理后的模型无法承接时，仅在调用方已核验连续输入与归还ACK后按当前方向满幅保守重建；日志seeded明确标识。首次未知持键仍需真实全松同步；未知ACK、断流、失焦和安全失信不通过此重建绕过。

## 对比操作

只使用NVIDIA配置。本包只更新NVIDIA Worker；继承的其他Provider保持原版，未进行本次实验验证。
原包使用原入口，本包使用Prepare产生的唯一Launch命令，不能同时运行。
在相同地图、武器、目标、按键与其余参数下测试。辅助页标题应显示“自动急停（HUD参考实验）”；固定反向时长置灰，原18ms等待保留。

依次观察：持续方向与功能键入目标；AD往返；目标消失与重新出现；持方向切刀/枪并持续或重按功能键；松键与End急停。
请在当前会话说明哪版更稳、哪一步出现等待/不释放，以及大致时间。无需手工填观察文档。

Prepare/Recover由代理执行；Launch仅由用户前台执行，不自动武装或自动按键。
日志记录HUD请求初态、保守重建、逐轴计划、ACK、取消；ACK和软件模型均不能证明游戏实际停稳。

实验配置键auto_stop.experimental_hud_model默认false；本包设true，每次启动固定选择一种策略。该文件也可用于还原对比条件，但日常原版入口不需要改配置。

2026-09-22节奏微调：初始零报告ACK后若已生成反向命令，立即重进完整输入/许可核验，免去额外1ms轮询等待；不减少模型制动时长或18ms等待。HUD急停评估为旧方向UP到相反方向DOWN间隔，会包含恢复原方向，不能按聚合偏晚量直接缩短制动。
