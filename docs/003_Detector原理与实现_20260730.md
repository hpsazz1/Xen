## 1. 模块边界与目录

Detector 接收 OpenCV BGR 图像，输出与原图坐标系对应的检测结果。它不依赖截图来源，也不依赖瞄准控制实现。

```text
Xen/detector/
├── detector.h / detector.cpp       # 唯一公有接口与 pipeline 编排
├── session.h / session.cpp         # ONNX Runtime 会话和 EP 配置
├── preprocess.h / preprocess.cpp   # LetterBox 与张量排布
└── postprocess.h / postprocess.cpp # 解码、阈值过滤后的坐标还原和 NMS
```

内部类型位于 `detector::detail`。调用方只应包含 `#include "detector/detector.h"`。

## 2. 数据流

```text
cv::Mat（BGR）
  → LetterBox 等比缩放与 114 填充
  → BGR 转 RGB、HWC 转 CHW、归一化到 [0, 1]
  → Ort::Session::Run()
  → 按输出形状选择解码函数
  → 置信度过滤
  → 坐标还原
  → 同类别 NMS 与 top_k 截断
  → std::vector<Detection>
```

`InferenceProfile` 分别记录前处理、推理、后处理和总耗时。`detect_batch()` 当前只是顺序调用单张 `detect()`，不是 ONNX batch 推理。

## 3. 公有接口

公有接口定义在 [`../Xen/detector/detector.h`](../Xen/detector/detector.h)。

| 接口 | 作用 | 失败行为 |
|---|---|---|
| `Detector(config)` | 保存模型与后端配置 | 不加载模型 |
| `load()` | 创建 ORT 环境、配置 EP、加载模型并读取输入形状 | 返回 `false` |
| `detect(image)` | 执行单图 pipeline | 返回空 vector |
| `detect_batch(images)` | 顺序检测多张图 | 对每张图保留独立空结果 |
| `clone()` | 用同一配置创建并加载独立实例 | 当前未向调用方显式报告加载失败 |
| `reset()` | 释放当前会话并恢复未加载状态 | — |
| `profile()` | 返回最近一次检测耗时 | load 后、detect 前为零值 |
| `available_providers()` | 查询 ORT 可用 EP | 异常时返回空 vector |

最小调用示例：

```cpp
#include "detector/detector.h"
#include "log/log.h"

Log::init(LogConfig{});
Log::register_module("detector", LogLevel::INFO);

DetectorConfig config;
config.model_path = "models/yolo.onnx";
config.backend = BackendType::CUDA;

Detector detector(config);
if (detector.load()) {
    std::vector<Detection> detections = detector.detect(frame);
}

Log::shutdown();
```

## 4. 前处理

实现位于 [`../Xen/detector/preprocess.cpp`](../Xen/detector/preprocess.cpp)。缩放比例为：

```text
scale = min(target_width / source_width,
            target_height / source_height)
```

缩放后的图像居中复制到目标画布，多余区域填充值为 114。之后执行 BGR→RGB、`uint8`→`float32`、归一化和 HWC→CHW，最终创建形状为 `[1, 3, H, W]` 的 ORT 输入张量。

当前实现假设输入是非空三通道图像，尚未显式校验空图、通道数和动态输入尺寸。

## 5. 会话与后端

实现位于 [`../Xen/detector/session.cpp`](../Xen/detector/session.cpp)。可配置后端为 CUDA、TensorRT、DirectML 或 CPU。

| 后端 | 当前行为 |
|---|---|
| CUDA | 先查询可用 Provider；不可用时打印提示并让 ORT 使用 CPU |
| TensorRT | 直接追加 TensorRT EP；可选启用 FP16 |
| DirectML | 按 `device_id` 追加 DirectML EP |
| CPU | 不追加 GPU EP，由 ORT CPU Provider 执行 |

模型会话创建后读取第一个输入的形状，并只将动态 batch `-1` 改为 1。动态高宽、非法维度和多输入模型尚未处理。

## 6. 输出解码

当前调度逻辑：

1. 单输出且形状为 `[1, N, 6]` 时走 `decode_yolov10()`。
2. 其他三维输出按 `[1, channels, anchors]` 读取。
3. `channels > 5` 时走 `decode_yolov8()`，否则走 `decode_yolov5()`。
4. 统一应用 `conf_threshold`、坐标还原、同类别 NMS 和 `top_k`。

这些规则是当前代码行为，不等于已经验证的完整模型兼容矩阵。不同导出器可能生成 `[1, anchors, channels]`、转置布局、多输出 head 或端到端 NMS 输出；在没有真实模型样本和单元测试前，不能宣称覆盖所有 YOLO 版本。

## 7. 当前支持边界

| 能力 | 状态 |
|---|---|
| 单输入、NCHW、float 模型 | 已实现，待系统测试 |
| CPU / CUDA / TensorRT / DirectML 配置入口 | 已实现，待各后端构建验证 |
| `[1, N, 6]` 解码入口 | 已实现，待模型样本验证 |
| YOLOv5/v8 类输出解码入口 | 已实现，输出布局需重点验证 |
| 同类别 NMS | 已实现，缺少单元测试 |
| 多图顺序调用 | 已实现 |
| 真正的 batch inference | 未实现 |
| 动态高宽、多输入、端到端 NMS、分割、姿态、OBB | 未实现 |

## 8. 已知风险与验证重点

- `decode_yolov8()` 和 `decode_yolov5()` 的内存步进方式需要用真实导出张量验证是否与 `[1, channels, anchors]` 布局一致。
- `scale_detections()` 对模型输出是归一化坐标还是输入像素坐标存在隐含假设，需要针对每种导出格式建立测试向量。
- 输入为空或输入尺寸为动态 `-1` 时，前处理可能产生无效计算。
- TensorRT 与 DirectML 配置失败时尚未形成统一的 TRT→CUDA→CPU 降级链。
- `Session` 内部仍使用裸 `new/delete` 管理 ORT 对象，需要后续按项目 RAII 规范整改。
- 当前没有单元测试目录，无法证明解码、坐标还原和 NMS 的正确性。

这些事项已汇总到 [`todolist.md`](todolist.md)。扩展新模型或 EP 前，应先补齐固定输入样本、期望输出和后端构建验证。
