## 1. 模块定位

Log 是全局基础设施，负责将各模块日志统一写入控制台、轮转文件、调试文件和内存环形缓冲区。它不依赖 Xen 的其他业务模块，Detector 等模块只通过 `Log` 接口和日志宏使用它。

当前文件布局：

```text
Xen/log/
├── log.h      # 唯一公有头文件：配置、级别、Log 静态类和宏
└── log.cpp    # spdlog 异步线程池、logger 与 sink 实现
```

文档中的完整路径以仓库根目录为基准；源码中的包含路径以源码根目录 `Xen/` 为基准，因此使用 `#include "log/log.h"`。

## 2. 设计目标

- 日志文件 I/O 不直接在推理线程执行。
- 所有模块使用同一格式、目录和生命周期。
- Release 构建不生成 TRACE/DEBUG 调用。
- WARN/ERROR 能写入轮转文件，最近日志能从内存中提取或转储。
- 未初始化时日志调用安全返回，不向业务代码抛出异常。

异步模式只能隔离大部分 I/O；当前队列溢出策略为 `block`，队列满时调用线程仍可能等待，因此推理热路径必须继续限制日志频率。

## 3. 生命周期与模块注册

```cpp
#include "log/log.h"

int main() {
    LogConfig config;
    Log::init(config);
    Log::register_module("detector", LogLevel::INFO);

    LOG_INFO("detector", "模块初始化完成");

    Log::shutdown();
    return 0;
}
```

约束：

1. `Log::init()` 必须在任何 logger 创建前调用一次。
2. 模块名使用短字符串，例如 `detector`、`capture`、`aim`。
3. 退出前调用 `Log::shutdown()`，先刷新 logger，再关闭 spdlog。
4. 业务模块使用 `LOG_TRACE/DEBUG/INFO/WARN/ERROR`，不直接创建 spdlog logger。

## 4. 当前接口

公有接口位于 [`../Xen/log/log.h`](../Xen/log/log.h)。主要能力如下：

| 分类 | 接口 | 说明 |
|---|---|---|
| 生命周期 | `init`、`shutdown`、`initialized` | 创建或释放全局日志设施 |
| 模块 | `register_module` | 创建模块 logger 并设置初始级别 |
| 写入 | `write`、`writef` | 宏调用的底层入口 |
| 级别 | `set_level`、`set_global_level` | 运行时调整过滤级别 |
| 环形缓冲区 | `get_ring_buffer`、`dump_ring_buffer` | 读取最近日志或写入崩溃转储文件 |
| 工具 | `level_name`、`level_from_name` | 级别与名称转换 |

`LOG_TRACE` 和 `LOG_DEBUG` 仅在定义 `LOG_ENABLE_DEBUG` 或未定义 `NDEBUG` 时生效；其他构建中展开为 `((void)0)`。INFO、WARN 和 ERROR 始终保留。

## 5. Sink 与过滤规则

| Sink | 当前级别 | 默认路径/容量 | 用途 |
|---|---|---|---|
| 控制台 | INFO+ | 标准输出 | 人工观察关键事件 |
| 轮转文件 | WARN+ | `logs/detector.log`，10 MiB × 3 | 保留异常信息 |
| 调试文件 | TRACE+ | `logs/debug.log`，默认关闭 | 开发阶段完整追踪 |
| 环形缓冲区 | TRACE+ | 内存 1024 条 | Overlay 展示或崩溃转储 |

所有 logger 共享这些 sink。异步线程池固定为 4096 个队列槽和 1 个后台线程。

## 6. Detector 集成

集成代码位于 [`../Xen/detector/detector.cpp`](../Xen/detector/detector.cpp)：

- `load()` 记录模型加载开始、成功或失败。
- `detect()` 未加载时记录 ERROR 并返回空结果。
- 单次 pipeline 耗时和检测数量使用 DEBUG。
- 空检测结果使用 WARN，并限制为至少 5 秒一次。
- 解码路径使用 TRACE。

Release 热路径中的 TRACE/DEBUG 会在编译期移除；空结果 WARN 仍会进入热路径，但已经限流。

## 7. 构建集成

spdlog 由仓库根目录的 `CMakeLists.txt` 通过 FetchContent 引入。源码迁移后，构建文件应使用：

```cmake
add_library(log STATIC
    Xen/log/log.cpp)

target_include_directories(log
    PUBLIC  Xen
    PRIVATE Xen/log)
```

以上片段记录目标状态，不代表本次已修改 `CMakeLists.txt`；构建路径同步仍在待办清单中。

## 8. 已知差距

- `log.h` 为完成格式化模板而直接包含 spdlog，与“公有头文件不暴露 spdlog”的设计目标尚有差距。
- 全局轮转文件仍命名为 `detector.log`，后续多模块接入时应评估改为更通用的文件名。
- `LogConfig` 的容量和文件大小尚未校验非正数输入。
- 文件系统、格式化和 spdlog 初始化异常尚未在模块边界统一捕获。
- 崩溃处理入口、Overlay 展示和 INI 热更新尚未接入。
- Log 模块尚无独立单元测试和构建验证记录。
