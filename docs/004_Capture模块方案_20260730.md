## 1. 当前状态

Capture 尚未进入源码目录，当前仓库中不存在 `Xen/capture/`。本文只定义最小可落地边界，不把候选方案写成已实现能力。

Capture 的职责是从本机显示器或网络流取得最新 BGR 帧，并向 Detector 提供 `cv::Mat` 与采集时间信息。它不执行模型推理，也不计算瞄准控制命令。

## 2. 首期采集方式

按隔离强度从高到低排列：

| 优先级 | 方法 | 配置值 | 数据来源 | 状态 |
|---|---|---|---|---|
| 1 | NDI 网络接收 | `ndi_capture` | 主机 NDI Screen Capture → 辅机 NDI SDK | 待实现 |
| 2 | UDP 推流接收 | `udp_capture` | 主机 FFmpeg gdigrab → MJPEG/UDP → 辅机 | 待实现 |
| 3 | Desktop Duplication | `duplication_api` | 本机 `IDXGIOutputDuplication` | 待实现 |

首期只保留这三种方式。其他采集 API 应在出现真实兼容性或性能需求后再评估，避免扩大实现面。

## 3. 统一输出契约

建议所有后端通过同一抽象输出：

```cpp
struct FrameTiming {
    std::uint64_t sequence = 0;
    std::chrono::steady_clock::time_point captured_at;
};

struct CapturedFrame {
    cv::Mat bgr;
    FrameTiming timing;
};
```

统一约束：

- 图像格式为 OpenCV BGR，与 `Detector::detect(const cv::Mat&)` 直接衔接。
- 时间戳使用单调时钟，不能使用会因系统校时回拨的墙上时钟。
- 队列只保留最新帧；消费者落后时丢弃旧帧，不累计延迟。
- ROI 裁剪必须保留相对完整画面的偏移量，供检测框坐标映射回原始 FOV。
- 后端停止、断流或重连通过状态返回，不向 pipeline 抛出异常。

## 4. 建议目录

实施时遵守项目的单公有头文件与平铺规则：

```text
Xen/capture/
├── capture.h             # 唯一公有接口、配置和帧结构
├── capture.cpp           # 工厂与统一编排
├── duplication.cpp       # DXGI Desktop Duplication
├── ndi_capture.cpp       # NDI 接收
└── udp_capture.cpp       # UDP/MJPEG 接收
```

这是目标结构，不代表文件已经存在。新增依赖或修改 `CMakeLists.txt` 前必须先确认。

## 5. 实施顺序

1. 定义 `CapturedFrame`、状态返回和最新帧队列，并为队列补单元测试。
2. 实现不引入新第三方依赖的 Desktop Duplication，打通本机最小闭环。
3. 记录帧率、端到端延迟、丢帧率和重连时间。
4. 基于实测结果依次接入 UDP 和 NDI；新增依赖前单独评审。
5. 将 ROI 坐标映射与 Detector 输出还原纳入集成测试。

具体优先级只在 [`todolist.md`](todolist.md) 维护，避免多份清单失去同步。
